## 4. Deviations and decisions taken alone

1. **Scattered state is information, not a warning.** The design said warning. The subject is its spelling, and the first run on this repository showed `self` "compared with 52 literal values in 14 files". The receiver is now excluded and the rule does not block.
2. **Bound arrow functions are routines** in TypeScript and JavaScript; a class field holding one is a method, not a field. Without this most TypeScript code would not be measured as routines.
3. **Metric points carry the spec, not component and task** (code-constraints 13.3 names all three). Component and task are on the finding records; on metrics they would multiply the series.
4. **`deny.toml`** excludes the native crate `kiro-code` from the wasm dependency graph, because its parse stack pulls a directory walker the sandbox policy bans. The engine does not depend on it. Made in the evening, listed again for review.
5. **`cpd-core` and `cpd-tokenizer` not adopted.** The tokenizer brings 122 crates and its own lexers; the code lines come from the syntax tree the metrics already use. The window policy over those lines (about 150 lines) is the only detection algorithm written.
6. **`git show` per file** instead of `cat-file --batch` for the before side.
7. **Not built although specified**: `CODE_NET_GROWTH` (no configured maximum exists), strict mode, `CODE_BASELINE_STALE` as a finding (the reason is in the coverage line), settings for duplicates and locality in the configuration file.
8. Task plans of clone-constraints and code-locality-data were marked approved on the strength of "complete the scitools port first".
